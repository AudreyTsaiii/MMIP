## Quiz 1: 彩色影像轉灰階影像

### 目標
將 RGB 彩色影像轉換為灰階影像，並比較自訂 NumPy 實作與 OpenCV 內建灰階轉換函數的表現。

### 方法
- OpenCV：cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
- NumPy：自訂灰階轉換函數，使用 RGB 通道資訊進行計算

### 評估指標
- 重複執行 N 次後的平均執行時間
- 兩種方法之間的最大差異
- 兩種方法之間的平均差異
- 原始圖與灰階輸出圖的視覺比較

### 結果分析
OpenCV 的實作通常較快，因為它是經過高度優化的 C++ 程式碼。NumPy 實作也能得到相近結果，且便於理解與修改，但實際執行速度通常較慢。從視覺結果來看，兩者的輸出影像很接近，肉眼觀察來看，會覺得整體的灰度會再更深一點；從數值角度來看，差異很小

### 進階討論
簡單的通道平均法容易實作，但更常見的灰階轉換公式是加權平均：

Y = 0.299R + 0.587G + 0.114B

這個權重會將綠色通道視為對亮度最重要的成分，因此更符合人眼對亮度的感知。此作業透過比較 OpenCV 與 NumPy 兩種方法，展示了演算法可讀性與計算效率之間的取捨。

## Quiz 2: Histogram Equalization

### 目標
使用 Histogram Equalization 提升影像的明暗對比與動態範圍，使低對比影像看起來更清晰。

### 方法
- OpenCV：cv2.equalizeHist()
- NumPy：使用直方圖與累積機率分佈（CDF）自訂實作

### 評估指標
- OpenCV 與 NumPy 的執行時間比較
- 處理前後影像的視覺比較
- 處理前後灰階直方圖比較
- 轉換後影像的數值差異比較

### 結果分析
Histogram Equalization 對低對比影像效果明顯，尤其當影像亮度集中在窄範圍內時，可以顯著提升整體可見度。OpenCV 版本通常較快，而 NumPy 版本稍慢，兩者的影像增強效果相近，差異主要存在於執行效率與實作方式。

### 進階討論
這種方法適合處理偏暗或偏亮且分布不均勻的影像，但若原始影像已有過強的亮暗差距，Histogram Equalization 可能造成過度增強，導致影像不自然。這時候 CLAHE 通常更穩定，因為它會針對區域性亮度做局部增強，而不是單一全域調整。

## Quiz 3: 梯形校正與透視轉換

### 目標
將斜拍的影像利用 Perspective Transformation 校正為正視影像，恢復較接近正面觀察的結果。

### 方法
1. 使用 Canny 邊緣偵測找出影像邊緣。
2. 找出最大輪廓並逼近四邊形。
3. 將四個角點依序排序。
4. 計算透視轉換矩陣。
5. 對影像進行 warpPerspective 修正。
6. 若自動偵測失敗，則使用手動選點作為備用方案。

### 結果分析
當影像邊界清楚且為明確四邊形時，自動校正效果較好，修正後的影像視覺上會更整齊、更接近正視圖。然而，此方法非常依賴影像條件，例如陰影、反光、邊角圓滑、背景雜訊等都可能影響校正結果。

### 進階分析：不同拍攝角度下的校正效果與失敗條件
我測試了不同拍攝角度與不同情況下的校正效果，發現演算法在以下情況會開始失效：

- 邊角較圓、模糊，導致角點難以正確偵測
- 文件邊界不是嚴格的矩形，造成四邊形估計失敗
- 陰影或反光遮住文件邊緣，使 Canny 邊緣檢測失真
- 拍攝角度過大，導致透視變形過於嚴重
- 背景具有複雜紋理，容易被當成偵測輪廓
- 物件是書本而不是平面紙張，因為書頁不完全平整，頁邊可能有弧度

從實驗結果來看，當偵測到的邊界不再是乾淨的四邊形時，演算法就容易失敗，此時 contours 或 HoughLinesP 可能會找錯邊或找不到四個真實角點。這種情況特別容易發生在書本上，因為書頁邊緣常常不完全直線、表面可能有彎曲、陰影與反光也更明顯，因此比單張平紙更難校正

## Quiz 4: 影像拼接

### 目標
使用特徵偵測與匹配方法，將兩張具有重疊區域的影像拼接成一張更大的影像或全景圖。

### 方法
- 先對兩張影像進行前處理，若亮度不均時加入 CLAHE 增強局部對比
- 接著使用 SIFT 檢測關鍵點與描述子
- 再利用 BFMatcher 和 Lowe ratio test 篩選可靠匹配
- 透過 RANSAC 估計 Homography，將第二張影像對齊到第一張影像座標系
- 最後進行畫布擴展與重疊區域融合，完成影像拼接

### 結果分析
當兩張影像有足夠重疊範圍、光線相近、且特徵點穩定時，拼接效果通常較好；此時匹配點數量足夠多，Homography 估計較可靠，最後拼接結果也更自然。

### 進階分析：不同亮度、拍攝角度與重疊範圍下的拼接效果
我觀察了不同條件下的拼接結果，發現以下情況會使演算法開始失敗：

- 重疊區域太小，導致匹配點不足
- 影像具有低紋理區域，特徵點不足

影像拼接在重疊範圍適當、光線條件穩定、視角差異不大時表現最佳。一旦重疊不足、角度過大或亮度不均，匹配點數量下降且錯誤匹配增加，最終導致拼接失敗。
